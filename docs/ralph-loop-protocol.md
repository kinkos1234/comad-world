# C7 — Ralph식 장시간 루프 실험 프로토콜

> 2026-06-11 benchmark-vs-world 리포트의 C7 항목. 2026-07-08 사용자 승인으로 확정.
> **신규 루프 엔진을 만들지 않는다** — 기존 자산 3개를 묶는 실행 규약이다.
> (근거: 같은 리포트 D절 "단일 만능 시스템·미사용 기능 축적 = 2026 안티패턴")

## 적용 조건 (전부 만족해야 시작)

1. **잘 정의된 spec** — `/comad-sdd` 로 작성된 Spec + 완료기준(acceptance criteria) 문서가 존재
2. **검증 가능 완료조건** — 각 기준이 test/gate/관찰 중 하나에 1:1 매핑됨 (사람 판단 불필요)
3. **되돌릴 수 있음** — 격리 브랜치/worktree 에서 진행, 실패 시 폐기 가능

셋 중 하나라도 없으면 Ralph 루프 부적합 → 일반 세션 작업으로.

## 실행 규약

| 단계 | 도구 | 역할 |
|---|---|---|
| Spec·완료기준 | `/comad-sdd` | 목표를 검증 가능 체크로 고정 |
| 루프 본체 | `/autoresearch` | 변경→측정→keep/discard 자율 반복 |
| 진행 측정 | `harness-report --read-only` + 과제별 metric | "좋아지고 있나" 수치 추적 |
| 정지 조건 | 아래 3종 | 무한 루프 차단 |

**정지 조건 (OR)**:
- 완료기준 전부 PASS (성공 종료)
- 연속 K=3 iteration 동안 metric 개선 0 (수확 소진 — 중단 후 에스컬레이트)
- 벽시계 예산 초과 (기본 4h, 시작 시 명시)

**보고**: 종료 시 `.comad/reports/impl/ralph-<slug>.md` — iteration 수·metric 궤적·keep/discard 목록·최종 검증 결과. Discord 요약 1회.

## 첫 실험 후보 선정 기준

- 후보가 나타나면 이 문서 하단에 기록하고 사용자에게 제안한다.
- 좋은 후보: 헤드리스 sim 으로 측정 가능한 성능/정확도 과제 (예: OCR recall, 물리 파라미터 튜닝 — [[feedback_headless_sim_pattern]])
- 나쁜 후보: 미감 판단 필요(디자인), 완료기준이 "사용자 만족"인 것
